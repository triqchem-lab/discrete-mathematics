# 工具调用循环陷阱（2026-10-01 实测）

## 症状
会话里对**同一批文件反复发起 `grep` 查询**，每次结果几乎一样、没有新信息产出，连续十几轮原地打转，烧掉预算（100% 到线禁取证工具）也没拿到答案。人类看不下去，直接说「不要使用grep」「你陷入循环了」。

## 判据（区分「工具选错」vs「用法打转」）
- **grep 本身不是低效工具**：查内容匹配是它的本职，一次调用返回带行号的匹配列表，比反复 `read` 大文件肉眼找省得多。**低效的是「同一个查询打第 4 次」**，不是工具选择。
- **真正该拦的信号**：同一工具 + 同一参数（或等价参数）连续出现而结果无增量 ⇒ 循环，该停。
- 预算闸门会拦（同一工具同参数第 4 次），但**在被拦之前模型自己就该停**——拿到答案就结束，不要再发起「确认一下刚才的结果」式的重复查询。

## 做法
1. **一次查询拿到行号 → `read` 关键区段确认上下文 → 结束**。不要「grep 完再 grep 一遍确认」。
2. 查依赖/拓扑用对口工具：`proof_graph`（解析 import DAG）、`proof_dag action:"search"`（查台账），比手写 grep 更准。
3. 只是想列文件/目录 → 用 `ls`/`glob`，不是 `grep`。
4. 怀疑自己在打转时：停手，改用 `read`（或直接凭已有信息行动），而不是换一个等价的搜索调用。
5. 人类说「不要用 X」通常是拦**循环**，不是给工具拉黑——换工具后照常工作即证明如此（本例改 `read`/`ls` 后正常完成）。

## 证据
- 本会话：连续 ~40 次 `grep` 同一批 `docs/`、`src/Sovereign/Analysis/` 文件，结果重复；被人类两次纠正后改用 `read` + `ls`，一次完成勘察并交付。
- 关联纪律：`docs/techniques/README.md` 约定「引用的每个 Agda 符号名必须能 grep 到」——**grep 是文档防漂移的标准手段**，别因这次循环把它当坏工具。

## 一句话
**问题是「打转」，不是「grep」**：拿到答案就停，重复查询第 2 次出现时就该换路。
