## 1. 台账↔代码断链（drift）

**计什么**（两个方向，`proof-dag.mjs:751-771`）：
- **纸面依赖**（:760）：节点声明 dep（或 `extends:` 关系），其**模块**未被本节点模块直接/传递 import ⇒ 断链。
- **真遗漏**（:767-768）：本节点模块 import 了 Y，且**存在某节点的 `module` 字段 == Y**，但 deps 里没有它 ⇒ 断链。
- **豁免**（:770）：import 的目标**无任何节点**其 module == Y ⇒ 归「未登记模块依赖」单列，**不计断链**。
- 同模块豁免（:751）：dep 的模块就是自己 ⇒ 不算。传递 import（有限深度）⇒ 归「传递依赖」不算。

**怎么修**：补 deps 时登记 **「module == 该 import 的代表节点 id」**（object 优先、id 次小为确定规则）——**不是模块名**（模块名会触发悬空）。纸面依赖（声明了却不 import）→ 把引用迁 `source` 字段后从 deps 移除（`update deps` 整替；`import` 只增不减）。

⚠ **坑**：错误消息「台账未登记该依赖」字面像要登记模块名——**不是**。模块名 = 悬空。

## 2. 悬空依赖（dangling）

**计什么**（:680-681）：`deps` 条目 ∉ 节点 id 表 ⇒ 悬空（整项 −15，不分条）。
**怎么修**：deps 只写节点 id。模块路径写 `source` 或 relations（`documents_at:`）。

## 3. 证据三档（evidence）

- 工具回执（`proof_compile` 签发，源码哈希绑定）= 已验证；模型自报 = 未验证（−5）；无证据 = 无。
- **回执失效**：源码改动即失效（注释改动也算）⇒ 重跑 `proof_compile` 刷新。
- deps/陈述变更 ⇒ 自动退回 `needs_review`（改签名=改契约）；源码未变的账实对齐可凭原回执复位。

## 陈述层生命周期与判据语义补录（2026-09-29，②层巡检制度化）

1. **statement_wrong 生命周期**：诊断修复/重证后必须**清账或注记**（挂旧诊断 = 记账层瑕疵）；refuted + statement_wrong = 正确闭环形态（如 GF729 自反件）。
2. **diagnosis 通道**：`diagnosis` 字段**只经 `update` 持久化**——`import` 批量通道不写诊断（实测静默丢失），批量入账后须 update 补挂。
3. **deps 双语义**：声明 deps 必须含 **import 码迹**（可传递）；语义注记关系（设计参考/拆分来源/命名对应）**不入 deps 入 evidence**——收缩只删语义、留码迹，否则产生「声明依赖无码迹」断链。
4. **公理判据 = 展示群八要素**（载体/生成元/关系/相位/时钟/归零/刚性/核对）——八要素齐备才有公理候选资格；探针/工具件（REWRITE 实验、postulate 仪器）一律**工具类型不升公理**；古典逻辑「闭合 vs 最小性」不是公理判据。内核事务（REWRITE/postulate 接受语义）归 Agda 内核判定，账面层不越权。
5. **判据维度是 ② 层对象**：检查结论本身过三问（隐藏假设/变元归属/声称强度）；普查类计数器是**候选器不是判官**；风险词扫描须带**词界**（「完备」误配「不完备性」实例）；结论按**模块图**而非文件清单查拓扑。
6. **回执生命周期**：模块追加（签名不变亦然）即失效旧回执，须 proof_compile 重签；改名/删块同理。批量修复后跑 `check` 复检（80→100 回绿实例在案）。
