## 七、合法/非法表述对照

### 7.1 本源 vs 投影

| 非法（投影误当本源） | 合法 |
|----------------------|------|
| Z/12Z 是涡旋代数本体 | DC（Z/3⊕⟨α⟩）是十二进制代数核；Z/12 加法是其群投影 |
| 十二进制 = 模 12 环 | 十二进制时钟 = 3 加 × 4 乘；模 12 环是另赋乘法的投影 |
| GF(3) 只是 Z/12 的阴影、非基础 | GF(3) 与 ⟨α⟩ **共同生成** DC；π₃ 是 DC/C₁₂ **落到** GF(3) 的投影 |
| 12 不可作 3×4 理解 | 周期 12 **就是** 3×4 的联合周期；「根」指基数/闭环，不指不可分解 |

### 7.1b ★★ **论证层次纪律**（2026-10-21 实例入册）

> **触发**：审核 `dc-presentation.rigidity = rho` 时，本地智能体的论证顺序是
> 「查 `rho` 的消费者（43 处）→ 确认 `rho` 在 `D₁₂` 里合法 → 保留 `rho`」
> —— **结论对，但论证起点错**：从「消费者」出发，而不是从「层次」出发。

#### 判据：**可见性 ≠ 透明性**

| | 可见性（visibility）| 透明性（transparency）|
|---|---|---|
| **表现** | 有消费者、有定理、能被引用 | 属哪一层、显式构造、穷举可验证 |
| **典型** | `rho` 有 43 处引用、`rho-is-inv` 已证 | `μ` 逐元素显式构造、`refl` 可验证 |
| **所在层** | **投影**（`D₁₂`、`C₁₂`、`R₁₂`）| **本源**（12 进制、`DuodecClock`、Frobenius）|
| **能回答** | 「它在这个结构里重不重要」| 「它属不属于本源」|
| **不能回答** | ✗ 它属哪一层 | ✗ 它在投影层合不合法 |

**⇒ 「重要」不等于「本源」** ✓ —— 消费者多只说明投影层结构重要 ✗

#### 正确的论证顺序（四条）

```
① 先查本源/投影表（本文件 §五、§7.1）
     → 确定被判对象（rho）与判据（八要素 ⑦）各属哪一层
② 若不同层 → **不能**用一个的合法性支持另一个 ✗
③ 本源层判据必须用**本源层论证**（域论：σ 固定素域）
     投影层判据才可用**投影层论证**（群论：p ↦ p⁻¹）
④ 结论可相同，但论证起点必须是「层次」，不是「消费者」
```

#### 本案的正确链条

```
❌ 错误起点：查 rho 的消费者（43 处）→ 合法 → 保留
✓ 正确起点：查本源/投影表
     → rho 在 D₁₂ 里 → D₁₂ 是投影 → rho 的合法性是投影层的
     → rigidity 是八要素 ⑦ → 八要素是本源的
     → 两者不同层 ⇒ rho 不能充当 rigidity ✗
     → rigidity = mu（本源）✓，rho 保留在 D₁₂（投影）✓
```

#### ★ 与「上帝视角 / 透明性」的精确对应（见 `40-transparency-vs-refutation.md`）

> **投影层的对象是「被遮挡但可见」的** —— 有消费者、有定理，
> 但它们的合法性来自投影结构，不是本源。
>
> **用可见性代替透明性，正是连续统数学「用反证法看到点的性质、却看不到点本身」的同构错误** ✗
>
> | | 连续统数学 | 本次错误 |
> |---|---|---|
> | 看到什么 | 点的**性质**（反证法）| `rho` 的**合法性**（43 消费者）|
> | 看不到什么 | 点**本身**（构造）| `rho` 的**层次**（本源/投影）|
> | 错误类型 | 用可见性代替透明性 | **同构** |

### 7.5 进制 ≠ 位域（**不同范畴**，2026-09-13 登记）

| | **进制**（numeral base / radix） | **位域**（digit field） |
|---|---|---|
| 是什么 | 记数法：位值权重 `b^k`、位值域 `0..b−1`、逢 b 进一 | 字内的一段字段：**状态数**（容量）与划分 |
| 变量 | 基 `b`（一个数） | 容量 `C`（一个数）与其分解 |
| 代码 | `Sovereign.Format.Positional` / `Doz` | `Sovereign.Format.DigitField` |
| 桥 | —— | `Sovereign.Format.DigitRealization`（**双射**，不是等号） |

| 非法 | 合法 |
|------|------|
| 12 进制 = 3 × 2 × 2 | 12 **态位域**可由 1 个三态域 + 2 个二态域拼成（`DigitField.capacity-12`）；以 12 为底的**记数法**是 `Doz` |
| 十二进制一位 = 1 个 trit + 2 个 bit | 12 态**位域**与十二进制**数位**之间有一一对应（`DigitRealization.realize` / `separate` 互逆） |
| 三进制「不适合」以 12 为底的记数法 | 位域容量与布局是位域的事：按容量口径 27 个三态域与 43 个二态域都装 11 位十二进制数位；只有**固定 3 trit/位**的交织布局才有冗余 |
| 位域容量 = 进制的基 | 位域容量是状态数；进制的基是记数法的基。二者之间的换算属**桥** |
