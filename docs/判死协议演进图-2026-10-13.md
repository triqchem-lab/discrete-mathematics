## B. v3 的核心判据（全量）

| 判定要素 | 规则 |
|---|---|
| **活性** | `mtime`（文件系统时间戳）+ `git log`（提交历史/事件 stream）**双证齐**；缺一即「疑似」，双证同时落盘才算「存活」 |
| **死亡** | mtime 停滞 + git 无写入 + 探针 unreachable **三者合**（单一探针永不判死） |
| **失联形态（v3.1 新增——今日 routeB 案）** | 代理可 dispatch、但队列丢失**且WIP 落盘**（mtime 建）——按「fork 存体」处理：主台入域收尸接管，修型+补收（回执仍取 toolchain 签发） |

## D. 编队纪律（从判死学到的流程模式）

1. **长跑子代理必备失联计时**——dispatch 后超过略长于典型单件时长（3-40s 量级）无回报，立即验证 mtime+git（写域联合证据）；
2. **写域证据 vs 探针olerance**——探针消息是辅助；判定权在文件系统与 git；
3. **fork 存体处置（三步）**：①读 WIP 确认内容 ②主台修型（只修语法/边界一致，不改语义结构）③复编取回执 + ledger 收账；
4. **诚实边界**——判死 vs 存活是**判定行为**不是**能力评价**：runtime/queue 故障按环境记 `journal kind:"limit"`，不扣分；
5. **权限纪律**——主台接管时**写域清空规则不变**（非原代理的接管二改仅限「语法适配」级别——**语义级保留**原代理成果结构，回执复取哈希绑定）。

**v4 展望（提请人类裁决作）**：would help 变体——长跑代理 dispatch 时显式注入 `timeoutMs` + 启动即刻 mirror status ping，以求双证链自回落。**未人类批准不启用**（仅记录为候选）。
