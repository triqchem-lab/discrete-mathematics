# 证明技术：配对弹出（pair-popping）

**日期**: 2026-09-13　**状态**: 已验证（两次实战，Agda 内核通过）　**适用**: Agda 构造性证明
**证据**: 回执 `15e868c2` / `e4b8ffb9`（M9 Jacobi）、`0f6d406e` / `3b49fa63`（det 乘法性）　**符号名**: 见 §3（均已在源码 grep 核对）

---

## 1. 一句话

当目标是**交换、结合**的和式（`⊕`），且其中有些项**归一到字面形式后互为相反数**（`t` 与 `neg t`）时：
用一次「四项重排」把这对项挤到相邻位置，再用「逆元 + 单位元」消掉，剩下的项继续。
**全过程不对任何变量做分情形穷举。**

它的价值不在「优雅」，而在**把穷举证明换成结构证明**：本库三次实战把 **729**、**6561**、**729** 条 `refl` 子句全部换成结构证明并**并入主模块**（分别压成 1 行 / 1 行 / 59 行）。

## 2. 适用判据（能不能用）

| 条件 | 说明 |
| --- | --- |
| ✅ 交换结合的和 | `⊕` 满足 `comm` / `assoc` |
| ✅ 有逆元 | `x ⊕ negate x ≡ 0`（`inverse`）与单位元 `0`（`identity`） |
| ✅ 项可归一 | 能把项归一到**字面相同**（矩阵乘法用 `assoc`、域乘法用 `comm`）；否则「相同」只停留在语义层，`swap4` 打不到 |
| ✅ 至少一对落在块首 | 否则先做对齐（§4） |
| ✅ **先分子型** | **相消型**：两端含「同项兼相反数」（`t` 与 `neg t`）—— 工具 `swap4` + `cancel-pair`；**置换型**：两端只是**同项异位**（无符号变化）—— 工具 `⊕-swap2` + `block-swap`。两类工具**不通用**，先判型再动手（§4.3 是置换型的首例） |
| ❌ 反例 | 和不交换 / 无逆元 / 配对只在高阶意义上成立（需三角函数恒等式、极限交换等） |
| ❌ **表 vs 公式的一致性检查** | 若运算本身是**表定义**（如 `_⊗_ : G → G → G` 由 24×24 子句给出），而待证命题是「该表与某个公式一致」（如 `toMat (x ⊗ y) ≡ mulMat2 (toMat x) (toMat y)`），则**穷举就是内容**：表的每一项都是独立数据，符号化只会把 24×24 重新引回来（需生成元 + 字范式论证，成本不低于原穷举）。**先判运算的定义形式，再决定是否值得构造化** —— 实例：`Structology/SL23Cayley.agda` 的 `toMat-hom`（576 = 24² 条 `refl`，`:681-1257`），其模块头已注明「封闭性亦由 det 乘法性保证，此处显式穷举与理论一致」 |

## 3. 核心两步与三件套

**① 弹出（pop）** —— 四项重排：

```
(A ⊕ B) ⊕ (C ⊕ D) ≡ (A ⊕ C) ⊕ (B ⊕ D)        -- swap4
```

取 `A := t`、`C := neg t`，即得 `(t ⊕ X) ⊕ (neg t ⊕ Y) ≡ (t ⊕ neg t) ⊕ (X ⊕ Y)`。

**② 相消（cancel）** —— 逆元 + 单位元：

```
(t ⊕ neg t) ⊕ Z ≡ Z                            -- cong (· ⊕ Z) (inverse t) ▷ identityˡ Z
```

n 对相消 ⇒ 2n 项降到 0，或降到「真正的余项」。

| 工具 | 作用 | 本库实例（均已核名） |
| --- | --- | --- |
| `swap4` | 弹出 | `Lie.LieAlgebra.mtadd-swap4`；`Jacobian.jac_Matrix.⊕-swap4`（Trit 版，因 `⊕` 是 `infix 20` 非结合，需自备一份） |
| `cancel-pair` | 相消 | `Lie.LieAlgebra.cancel-pair : (A ⊕ neg A) ⊕ B ≡ B`；**另需头部反向的变体** `cancel-pair' : (neg A ⊕ A) ⊕ B ≡ B` —— 两种都要 |
| **对齐（align）** | 让弹出可生效 | `assoc` / `comm` 把目标对挪到「左块首 / 右块首」；M9 用 3+3 步、det-mul 用 1 步 |
| `⊕-swap2` | **置换型**用：2 项交换 | `CyclicGF27` 探针 `⊕-swap2 : x ⊕ (y ⊕ z) ≡ y ⊕ (x ⊕ z)`（3 步：`sym assoc` ▷ `cong (· ⊕ z) (⊕-comm x y)` ▷ `assoc`） |
| `block-swap` | **置换型**用：4 项块交换 | `CyclicGF27` 探针 `block-swap : bf ⊕ (bf ⊕ (ce ⊕ ce)) ≡ ce ⊕ (ce ⊕ (bf ⊕ bf))` |

**对齐是唯一需要动脑的部分**：`swap4` 只交换两个 4-项块的**中间两项**，所以两个成员必须已在各自块的头部。

**char 3 的第二类相消（第 4 战新增）**：特征 3 上「同项」不只有「配成相反数」一种死法 —— 三个同项也归零：`⊕-char3 : (t ⊕ t) ⊕ t ≡ T₀`（因 3t = 0）；而 `⊕-double : t ⊕ t ≡ ⊖t` 把「两同项」就地转成「一对相反数」，于是**配对相消与三连相消可互相归约**。
判据：把两端展开成**同一单项式基上的 GF(3) 线性组合**后，逐单项式的**系数和必须 ≡ 0 (mod 3)** —— 系数是 `+1,+1,+1` 走三连，是 `+1,−1` 走配对（这一步正是 oracle 该给的输出）。

## 6. 十一条陷阱（全部实战踩到，附报错类型）

1. **`cancel-pair` 的头部方向**：`(A ⊕ neg A)` 与 `(neg A ⊕ A)` 是**两个不同引理**，不能互替（`UnequalTerms`）。
2. **归一化后必须引用归一化后的形态**：链条中途把 `n4` 重写成 `negate t4` 之后，后置步骤的类型/辅助定义**不能再写 `n4`** —— 二者只经引理相等、非定义相等（「名字 ≠ 形式」的典型）。
3. **`sym` 方向**：`assoc` 用于「展开」还是「收拢」取决于目标方向；写反即 `UnequalTerms`（该报错会打印两侧项，可直接读出修法）。
4. **对齐后仍可能差一次内部交换**：`(b⊗c)⊗(g⊗f)` 与目标 `(b⊗c)⊗(f⊗g)` 差一次 `comm`，需在「对到右端」时补齐。
5. **运算符优先级**：本库 `⊕`/`⊗` 是 **`infix 20` 非结合**，混用必须**全括号**，否则 `NoParseForApplication`（**解析错**，不是类型错，极易误诊）。
6. **「两端嵌套形状相同」≠「逐项对齐」**：§4.3 的第一版正是按这个直觉写的，被 `UnequalTerms` 证伪 —— 交换后**项序发生了置换**。**动手前必须把两端展开式逐项写出来比项序**（或先过 `proof_oracle`），不能只看括号形状；读编译器打印的两端全文通常比猜更快。
7. **嵌套 `where` 的作用域**：`eq0 = … where r0 = … h0 = …` 里 `r0` 引用同块 `h0` 会报 `NotInScope`（§4.4 实测）—— **把 where 块一律拍平到同一层**，别嵌套。
8. **`cong₂ _⊕_ p q` 的隐式参数可能推不出来**：报 `UnsolvedMetaVariables` / `UnsolvedConstraints`（打印 `(_x ⊕ Z) ⊕ _u = … : Trit`）。**降级为单参数 `cong`**：`cong (X ⊕_) q`、`cong (_⊕ Y) p` 逐槽改写，稳定得多。
9. **非结合算子的 section 也要全括号**：`negate A ⊕ negate B ⊕_` 不是合法 section（`NoParseForApplication`），须写 `((negate A ⊕ negate B) ⊕_)`。
10. **合并时别把「类型续行」当子句删掉**：本库签名常跨两行（`f : ∀ x y →` ↵ `  … ≡ …`），按「以 `f` 开头的行」切片会把**第二行类型**一并删掉 → `ParseError`。切片后**必须 `diff` 签名两行**（§7② 的加强版）。
11. **`sym` 不是习惯动作，先看引理的陈述方向**：§4.4 两处栽在这 —— `negate-⊕` 本身已是 `⊖(x⊕y) ≡ (⊖x ⊕ ⊖y)`（再套 `sym` 即反向）、`⊕-assoc` 的正向正是「左结合 → 右结合」。规则：**先看陈述，再决定要不要 `sym`**；报错会打印期望/实际类型，读它比猜快。

## 7. 配套纪律：替换类重构的五项交付证据

「穷举 → 结构证明」的替换**必须**附五项证据（两次实战均按此交付）：

| # | 证据 | 做法 |
| --- | --- | --- |
| ① | 子句数归零 | `grep -c` 对比替换前后 |
| ② | **命题未漂移** | `cp` 备份 → 替换 → `diff` 新旧**语句**行（逐字相同） |
| ③ | 主模块 `exit 0` 且 0 postulate | `proof_compile` 回执 |
| ④ | **具体点独立路径复核** | 原穷举＝一层验证；用 `refl` 直接计算若干具体实例，与结构实例落在**同一命题**上 |
| ⑤ | **下游引用者编译验证** | `grep -rln` 找引用者并逐个编译；⚠ 退出码必须 `rc=$?` **立即入变量**（`echo "$(cmd1): $?"` 会取到 cmd1 的退出码，是实测踩过的坑） |

## 8. 如何复用到新目标（操作序）

1. **先算**：用 `proof_oracle` 脚本把两端的展开写成（符号, 因子排序多重集）并相减 —— 残差为 0 且能列出相消对，才动手（本库脚本样例：`/tmp/detmul_pairing.py`、`/tmp/m9_pairing.py`，回执 `7c47fd5b…` / `23de115c…`）。
2. **在探针模块开发**：主模块编译慢且失败会污染其回执；探针只 `import` 所需模块，秒级编译。
3. **不手写巨型类型**：展开链的中间类型交给 Agda 从 `trans` 上下文推断（手写必与推断不一致）。
4. **归一化 → 对齐 → 弹出 → 相消 → 对右端 → `sym`** 六段式；缺一段都会 `UnequalTerms`。
5. 替换后按 §7 五项证据交付；探针用完删除。

## 9. 未做 / 边界（不得越过）

- **未机械化**：配对表仍是手推 + Agda 逐链验证；仅用 oracle **核对**过配对表，**没有**自动生成相消链。
- **未普遍化**：已覆盖「有限交换群/环上的 4 项块」（4.1–4.3）与「特征 3 子域嵌入的分量多项式」（4.4）；**8 项以上的多层重排未验证**。
- **不是银弹**：`swap4` 只处理 4 项块；n 对相消的对齐成本随项数增长（M9 是 3+3 步），更大情形需要更好的对齐策略或更通用的重排引理。
- **不适用于非交换/无逆元/高阶配对**（见 §2 反例行）。
