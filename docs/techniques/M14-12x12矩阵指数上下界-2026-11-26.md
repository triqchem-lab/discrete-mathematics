## 四、意外发现: C 位运算惯用法在三进制容器上失效（★ 三进制语义坑）

`main(){ …; return s2 & 255; }` 首跑 **exit=0**, 宿主 oracle **=64**——先算后验捕获分歧:

- **根因**（`trirv_cc.c:1698`）: C 前端把 `&` 映射为 **TAND = 逐 trit 最小值**（三进制逻辑
  AND 的自然选择）; 而 C 的 `x & 255` 惯用法是**二进制位与**（取模 256 的字节提取）。
- **为何恰为 0**: s2 = 57,340,224 = 243·235,968 → 三进制 243/81/27/9/3 位含 0 结构
  → trit-wise min(s2_trits, 255=100110₃) 塌到全 0。
- **为何 fib 基准从未炸**: fib 返回值恒 < 256 → min(x, 255) = x 巧合成立。
- **验证**: 裸 `return s2` 变体 → **exit = 64** = 宿主逐字一致 ✓（矩阵乘法本体完全正确）。
- **定级**: 非 VM bug——**C 位运算惯用法与三进制 TAND 的语义差**（设计层文档坑）;
  三进制下的字节提取应改写为算术式（`s2 − (s2/256)*256` 或 `%`）。
