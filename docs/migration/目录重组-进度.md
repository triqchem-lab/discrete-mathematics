## 关键教训（下次做同类重命名必读）

1. **同名碰撞**：桶名与文件基名相同会自吞——本项目 `Topology` 桶里恰有 `Topology.agda`，
   第一轮正则把 `Sovereign.Application.Topology.<X>` 改成了 `...Topology.Topology.<X>`（17 处）。
   **修法**：先写 module 行（权威值），再只对「裸引用」改写（lookahead 需同时排除 `.`），
   或全程用映射表的**精确名→精确名**替换。
2. **前缀吞并**：`BSD` 是 `BSD9`/`BSD_GF27` 的前缀 ⇒ 必须长名优先 + `(?![0-9A-Za-z_])`。
3. **`while read` 末行**：清单文件末行无换行时最后一项会被静默跳过（本轮 `Topology` 桶就漏跑了）。
4. **验收不能只看「桶内编译」**：import 改写会影响桶外消费者 ⇒ 需全库并行门禁（本轮 819/823）。
5. 4 个 `Laurent*` 失败是**既有**编译器 bug，不属于本次迁移责任——但**必须写明**，否则会被误读成迁移破坏。

## 阶段 2 的额外教训

6. **头注释不可作为分类依据**：`'algebra'` 这类泛词命中几乎所有 Algebra 模块头 ⇒ 首轮把 128 件塞进 `UniversalAlgebra`。
   **正确做法**：文件名优先（本库文件名描述性强）+ 泛词排除 + 人工表兜底。
7. **限定引用与子模块引用**：`Sovereign.Algebra.GF9.norm-mul`、`Sovereign.Algebra.ChainHom.Swap` —
   前者是「模块.标识符」，后者是子模块。用「词界排除 `.`」的正则会漏改（6 个桶因此编译失败）。
   **正确做法**：改为「按文件系统解析」——若某引用前缀解析不到文件，就按末段名唯一匹配到当前模块。
8. **`git mv` 两次搬家**是可接受的（先粗分、后细分），但每次都必须同步 module 行 + import，
   否则中间态会出现「名字对、路径错」的模块。
