# 回执重取报告（2026-10-14）

## 一、问题

六层目录重组的移动面用 `git mv` + 全库引用替换完成（471→472 口径，断链 0）。但**回执是内容寻址的**：回执 id = 源文件文本的 sha256（`plugins/agda-engine.mjs:286 sourceHashOf`），迁移改写了每个移动件的 `module` 行与 import 行 ⇒ 这些模块的旧回执**必然失效**。

工具口径（`proof_dag action:"check"` 首次）：

```
- 证据可信度: 347/563（工具签发回执）｜⚠ 未验证 213
- 回执失效: ❌ 213 个节点（回执与当前源码不符（文件已修改））
```

## 二、判据与口径

- **机器权威 = `proof_dag` 台账**（`~/.dsh/state/math-proof/dag-<sha1(workspace)[:12]>.json`，workspace=`/data/work/discrete-mathematics` ⇒ `dag-11083e096b45.json`，764 节点）。
- 回执 id 即当前源码哈希；`verifyReceipt`（`plugins/agda-engine.mjs:500`）三判：回执文件存在 / exitCode=0 / 源码哈希相符。
- 台账路径解析用**节点自己的 `module` 字段**（`plugins/proof-dag.mjs:1265 moduleText`）；迁移时该字段已更新为新模块名，故可用它映射当前文件。
- 重取回执**不修改任何源码**——只编译、只签发回执，符合「迁移面不改内容」与「探针不动」两条约束。

## 三、方法（三步）

1. **落清单**：逐节点读 `evidence` 里的回执 id → 取回执的 `relPath` → 按节点 `module` 字段映射当前文件 → 得 `922 条失效引用 / 401 节点 / 254 个待重编译文件`（另 3 组文件已不在库，见第五节）。
2. **预编译建缓存**：串行 `agda --guardedness <file>` 跑完 240 个待办文件（116 通过 / 1 例 rc=42），把 `.agdai` 缓存建好；此后 `proof_compile` 命中缓存，多数在 2–5 秒内返回。**为什么串行**：Agda 的 `_build` 全局共享，并发会互相踩。
3. **取回执 + 写回**：逐个 `proof_compile`（Laurent 线按既有裁决补 `--no-fast-reduce`，见 `prover_limits`），再用 `proof_dag action:"import"` 批量写回 `evidenceReceipt` + `evidenceVerified`（一次调用几十个节点，`import` 保留 `deps`/`note`/`statement` 不动）。

## 六、复现

预处理脚本与清单落在会话临时目录（`$TMPDIR`）：

- `classify_stale.py` — 从台账算出「节点 → 模块 → 当前路径」失效清单

- `make_import.py` — 按清单生成 `proof_dag import` 的 items 并记录已完成
- `batch_files.py` / `pending_prebuilt.py` — 文件级进度

判据只认工具输出：`proof_compile` 的 `exit 0` + 回执 id，`proof_dag check` 的「证据可信度 / 回执失效」两行。
