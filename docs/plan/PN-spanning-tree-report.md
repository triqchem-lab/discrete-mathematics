# π₁bt 课题：**生成树接口**研究报告

> 立项依据（四判据）：**离散化路径未定** 成立 ⇒ 立项。本报告是**数学路径设计**，不是实现方案；报告通过 ≠ 自动开工。
> 依赖：`_PN11`（顶点/边枚举 `Elem`/`Elems`/`toElems`）、`_PN12`（`TreeSec` 假设包 + 非树边对应）、`_PN13`（归纳树与计数）。

---

## 一、数学对象

**对象**：连通图 `G` 的**生成树**（spanning tree）——边集的一个子集 `T`，满足：① `T` 连通（沿 `T` 从任一顶点可达任一顶点）；② `T` 无环。

**载体**：`IsTree : (edge G u v) → Set`（树边谓词）+ 伴随的「到达性」数据。
**生成方式**（本课题采用）：**从基点 `a` 的 BFS/DFS 返回路径** `ret : (x : V G) → Walk G a x` —— 树边就是 `ret` 走过的边。这是**构造性**的（不需要选择公理）。
**关系**：
- 与图：`T ⊆ E`（每条树边是原图的边）；
- 与非树边集：**互补**（`filterE` 保留的正是补集）；
- 与计数：`|T| = V − 1`，`|E \ T| = E₀ − V + 1`（后者即 `rank-arith` 的被减数）。

---

## 二、经典路径

1. **存在性**：连通图有生成树 —— 经典证法用良基归纳或选择公理；**构造性版本**：从 `a` 做 BFS，每访问一个新顶点就记下那条边。
2. **边数**：树 ⇒ `|T| = V − 1` —— 对「顶点数」归纳。
3. **秩**：`|E \ T| = E₀ − |T| = E₀ − V + 1`。

## 四、严格设计（三步）

**步骤 (i) 定义生成树包**（`record`，关系入定义 —— 本库 presentation 惯例）：

```agda
record SpanningTree (G : DiGraph) (a : DiGraph.V G) : Set₁ where
  field
    ret        : (x : DiGraph.V G) → Walk G a x          -- 到达路径（构造）
    IsTree     : ∀ {u v} → DiGraph.edge G u v → Set      -- 树边谓词
    tree?      : ∀ {u v} (e : DiGraph.edge G u v) → Dec (IsTree e)
    tree-loop  : …                                        -- 环路平凡
    ret-tree   : ret 的边全为树边                          -- 「spanning」①
    flip-tree  : 树边的 flip 仍为树边                       -- 「spanning」②
    -- 不写「树边数 = V − 1」为字段（那是**导出性质**，见最小性判据）
```

> **最小性自检**：①presentation 关系 / ②结构公理 / ③可导出性质 —— 上述字段里 `tree?` 是**可判定性**（本库惯例，与 `_≟E_` 同类），`ret-tree`/`flip-tree` 是**spanning 的定义性条件**（不是可导出性质：`tree-loop` 是单向蕴含，推不出它们）；**「树边数 = V − 1」不许入字段**（它是要证的定理）。

**步骤 (ii) 存在性（BFS 构造）**：在「顶点有限 + 边可判定 + 图连通」的前提下，用列表折叠构造 `ret` 与 `IsTree`，并验证 `ret-tree`/`flip-tree`。
- 需要的额外基础设施：**「顶点有限」**（`V G` 可枚举成列表）—— 本库 `_PN11.Elems` 已给边的枚举，顶点枚举需补。

**步骤 (iii) 计数**：由 `ret` 的边集构造一棵 `_PN13.Tree`，并证 `ecount t ≡ |T|` 与 `size t ≡ V` ⇒ 用 `_PN13.ecount-size` 得 `|T| = V − 1`。

## 五、诚实边界（三分类）

| 类 | 内容 |

| **构造性不成立** | 无。BFS 构造是构造性的（无需选择公理）。 |
| **深定理（不短期开）** | 「任意连通图的生成树存在」在**无限图**上需要选择公理 —— 本库**只做有限图**，避开。 |
| **注释级-未证（需升级）** | ① `ret-tree`/`flip-tree` 目前只是**显式假设**（第 88–90 轮的权宜），不是从 `tree-loop` 导出的；② 「顶点有限」这一基础设施尚缺（`_PN11` 只枚举边）。 |
